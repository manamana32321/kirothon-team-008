# 로컬 확인 안내

사용자는 화면을 직접 보고 나서 머지한다. 몇 분 안에 끝나게 준비한다. 서버는 이미 떠 있고, 데이터는 필요한 상태로 만들어 두고, 어디서 무엇이 보여야 하는지 표로 준다. 기계로 볼 수 있는 것은 직접 보고, 사람 눈이 필요한 것만 안내에 남긴다.

개인 Claude Code 스킬 `local-check-guide`를 이 프로젝트(운동기, 로그인 없음, SQLite)에 맞게 옮긴 것이다.

## 안내 전에 할 것 (설명하지 말고 실행)

1. **이 워크트리에서 서버 띄우기.** 변경이 든 워크트리에서 `pnpm dev -H 127.0.0.1 -p <포트>`. 다른 워크트리가 포트를 잡고 있는지 `ss -ltnp`와 `readlink /proc/<pid>/cwd`로 확인하고, 겹치면 다른 포트를 쓴다. PR이 머지될 때까지 띄워 둔다.
2. **확인 전용 데이터.** `pnpm db:migrate`로 마이그레이션을 적용한 뒤 API로 `[검증]`이 붙은 새 그룹과 멤버를 만든다. 기존 그룹을 고쳐서 상태를 흉내 내지 않는다. 만든 그룹 ID와 초대 코드를 적어 둔다.
3. **기계로 볼 수 있는 것은 직접.** curl로 API 응답 코드와 본문, 페이지 200, SSE 이벤트를 확인한다. 결과는 안내의 "이미 확인한 것"에 숫자로 넣는다.
4. **사람 눈이 필요한 것만 남긴다.** 배치, 문구, 소리, 카메라, 두 창 사이의 실시간 반영처럼 화면에서만 보이는 것.

## 안내 메시지 모양

실제 값만 쓴다. `<그룹 ID>` 같은 빈칸을 남기지 않는다.

1. **한 줄:** 어느 워크트리에서 어느 포트로 떠 있는지.
2. **표:** 행은 `[화면 이름](http://localhost:포트/경로)`과 할 행동("알람 켜기 누르고 1분 뒤로 맞추기"). 열은 의미 있는 사람·상태(나, 친구 창, 알람 전/후). 칸에는 눈에 보여야 할 것 한 문장("친구 창의 내 줄이 '간다'로 1초 안에 바뀜"). "잘 되는지"는 쓰지 않는다.
3. **멤버 링크:** 로그인이 없으므로 창마다 쓸 그룹 링크와 닉네임. 두 번째 사람은 시크릿 창이나 다른 브라우저로 열어야 localStorage가 겹치지 않는다고 적는다.
4. **이미 확인한 것:** 직접 확인한 결과와 숫자.
5. **못 하는 것 / 주의:** 준비 못 한 것과 이유(카메라·마이크 권한, 소리 자동 재생, 실제 기기).
6. **정리:** 머지 후 지울 데이터와 끌 서버.

## 흔한 실수

| 실수 | 대신 |
|---|---|
| 기존 그룹의 알람 시각을 바꿔서 상태 만들기 | `[검증]` 그룹을 새로 만든다 |
| `<그룹 ID>`를 비워 두기 | 먼저 만들고 실제 값을 쓴다 |
| "기능이 잘 동작하는지 확인" | 보여야 할 글자나 요소를 정확히 쓴다 |
| 직접 돌릴 수 있는 curl을 사용자에게 시키기 | 돌리고 결과를 "이미 확인한 것"에 쓴다 |
| main이나 다른 워크트리에서 서버 띄우기 | 포트의 cwd를 확인하고 주소를 쓴다 |
| 두 사람을 같은 창에서 확인하게 하기 | 시크릿 창이나 다른 브라우저를 쓰게 한다 |
