# 사용자 컨텍스트

개발자 본인의 작업 성향과 규칙. Kiro가 매 대화에서 읽는다. 개인 신상과 다른 프로젝트 정보는 공개 레포라 뺐다.

## 응답
- 답은 한국어. 짧게, 결론 먼저.
- 웹 풀스택과 인프라는 기본 개념 설명 생략. 선택 이유와 trade-off만.

## 선호 스택
- 프론트: Next.js(App Router) + Tailwind CSS + shadcn/ui
- 백엔드: Prisma
- 인프라: 컨테이너(GHCR) + GitHub Actions, 홈랩 K3s + ArgoCD GitOps
- 패키지 매니저: pnpm

## 설계 성향
- LLM은 비정형 탐색에만, 굳은 패턴은 결정론 코드로 옮긴다 (Compiled AI). 단계마다 "LLM에 둘지, 코드로 옮길지" 명시.
- 선언적 관리, SSOT. 같은 정의를 두 곳에 두지 않는다.
- 아이디어 평가 축: 내가 진짜 불편한 문제인가, 세상에 필요한가.

## 작업 규칙
- 추정으로 단정하지 말 것. 명령 한 줄로 확인 가능하면 실행 후 말한다.
- 요청 범위만 수정. 주변 코드 리팩터·포맷 변경 금지.
- 코드에 설명 주석 추가 금지. 근거는 커밋 메시지·PR 본문에.
- 과설계 금지. 요청 안 한 기능·추상화·설정 옵션 만들지 말 것.
- 막히면 근본 원인부터. 우회책만 던지고 넘어가지 말 것.
